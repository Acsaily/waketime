# 统计卡片间距与周期导出设计

基于 `7159ce7`，增量 PR 目标 `refactor/eng`。监督任务授权自问式决策及实现，不改变 schema 3、计时权威、版本、单周期导出或全量备份。

## 自问式 grill（本轮工程决定）

- Q1：卡片间距是共享主题还是局部布局？先实际测量历史、统计卡片与正常卡片，定位层叠和容器关系；仅在对应 feature 修复实际原因，保持现有设计节奏。展开、收起、滚动、窄屏不溢出。
- Q2：范围是自然日片段还是完整作息周期？依现有历史/统计的本地起床日（`wakeDateOf`），起止均含，同日起床多周期默认全选（单日可精确选一个），跨午夜不截断，按起床时刻升序。选择依据不是 ID 字符串或睡着日期。
- Q3：快捷项与手动日期是什么关系？本周（周一至周日）、本月（自然月）、上周、上月、最近 7 天；默认本周；快捷按钮只填充两个可编辑日期框。未来日期可选但无记录不会生成文件；日期缺失、不合法或倒序明确提示。
- Q4：预览是什么？范围、记录天数、周期数、总睡眠、实际清醒和未结束周期数，用原有 `summarizeCycle`、统一选择函数与显示时刻。开放周期截至预览时刻，导出调用携带该时刻，数据以当前应用快照为准。不需要第二个确认步骤。
- Q5：格式？保留单周期 TXT/PDF/JSON、全量备份；新增周期 TXT/PDF/JSON 各生成一个文件，明确日期范围和聚合摘要，TXT/PDF 复用原周期明细且趋势仅计算选中记录，JSON 复用 schema 3 备份形状（仅含选中周期）；文件名 `waketime-period-<start>_<end>.<ext>`。PDF 仍由原生渲染，浏览器明确提示限制。无数据或非法范围禁用按钮，应用层再拒绝；共享导出锁，所有导出只读。

## 方案取舍

PR #2 首版的双卡片方案经负责人体验后被统一入口取代。当前采用一张「导出与备份」卡片：日期范围 → 必要时选择作息周期 → 一个动态预览 → 一组 TXT/PDF/JSON 按钮。单日仅一周期自动沿用单周期文件/统计（TXT/PDF 保留全历史趋势上下文）；单日多周期默认全部，可按 ID 与起床时刻精确选择一个；日期变化清除精确选择，多日范围不展示该控件。全量备份独立放在「数据」区，与恢复相邻，不受日期有效性影响。设置页共享既有操作锁，预览时刻传入两种导出路径。保留单周期分类汇总，范围预览保留总睡眠/实际清醒；不做双卡片、模式切换或多个文件。无新 store、schema、版本或平台依赖。

## 验收

合成数据验证跨度、同日起床多周期、跨月、开放周期、首尾日、非法/空范围、非匹配记录不泄漏、真实文件内容、PDF 端口请求、旧导出不变、导出无写入。浏览器 375×812/360×800 实际交互、滚动、截图和下载读回；静态、属性、差分、本地严格门；独立评审。真实手机、生产数据、MuMu 和发布均不在本轮范围。
