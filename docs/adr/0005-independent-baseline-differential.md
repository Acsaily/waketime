# ADR 0005：独立基线、差分与生产备份只读回归

- 状态：已采纳（用户确认 Q19、Q20、Q23、Q24；计划 Task 1/6/7）
- 日期：2026-11-26
- 来源：[实施计划](../superpowers/plans/2026-11-26-engineering-refactor.md)、[验证文档](../architecture/verification.md)

## 背景

行为保持式重构需要证明“旧版与新版在相同输入、时间和时区下结果一致”。如果预期值由候选实现生成，或测试直接 import 候选实现，差分就失去独立性。生产数据又包含私人备注、真实周期与分类，不能进入仓库、日志或外部服务。

## 决定

- 从 `8307835` 用 `git archive` 建立仓库外的隔离旧源码树，并在其中 `npm ci`；差分只通过固定绑定调用旧/新真实入口，不做输出归一化。
- 先跑自检：old-v-old 应零差异，六类故意扰动应被检出；再跑候选 vs 基线。
- 属性测试使用 fast-check 和独立 oracle；保留可重放 seed/path，失败可最小化复现。
- 生产备份只通过 `--backup <仓库外绝对路径>`、固定 `--now`、显式 `--tz` 进入本地只读差分；原文件不复制、不打印、不写回。
- 差分输出只使用受控字段词汇和聚合计数；真实备注、ID、路径、截图不进入追踪文档。
- 已知基线差异（TS/Java 合并备注/source、`null` 备注、重叠段统计等）先记录为契约，不在结构重构中偷偷统一。

## 后果

- “零差异”有可验证的检测器前提，不是空跑。
- 基线目录需要独立依赖，首次准备较慢；缺失时明确失败而非跳过。
- 生产回归能覆盖 JSON 数据与统计，但不能替代原生状态连续性/覆盖安装/通知栏 E2E。
- 任何预期值变更都必须说明是基线既有行为还是回归；后者必须修复。

## 验证

- `npm run test:differential:self`：old-v-old + 六类扰动。
- `npm run test:differential`：26 组合成案例、三时区、固定 as-of。
- `node scripts/verify.mjs private ...`：生产备份差分；当前记录为 16 周期 / 140 段、零字段/分类差异、原文件未改变。
- `tests/property/domain.test.ts`：独立 oracle、seed/path 重放自检。
- `contracts/timer-cases.json`：TS/Java 共同与分歧案例。

## 回滚

基线树损坏时从 `8307835` 重新 `git archive` + `npm ci`，不修改历史提交。若生产备份在运行中发生变化，立即停止并将该次结果视为无效；不尝试“修正”原文件。若差分检测器误报，先修自检/字段词汇，不得放宽原有行为断言。
