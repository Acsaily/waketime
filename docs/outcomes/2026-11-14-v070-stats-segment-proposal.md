# v0.7 方案：独立统计页 + 睡前时间（待分配）+ 分段手感

日期：2026-11-14。性质：**方案，未实施**。依据用户 2026-11-14 的决定、现有代码观察，以及新做的分段交互预览；没有修改 App 源码、`data.json`、schema 或版本号。

## 0. 已采纳的决定

1. 统计独立成页；导出移到设置；分类管理移到统计页，采用和历史页一样的滑动分栏。
2. 统计里**不计补觉**。
3. 周 / 月 / 年切换查看。
4. 折线做两版：**合计** 与 **单独某个分类**，可切换。
5. 分类管理入口按第 1 点放统计页。
6. 新增系统分类“睡前时间（待分配）”：不可删除，只可改名；分配后时间从它的占比里移走。
7. 拆分/合并/计次需要重做手感；先出方案与交互预览。

## 1. 导航与页面结构

### 主导航

从 4 个 tab 调整为：

```text
今日 / 历史 / 统计 / 设置
```

- 移除“导出”主 tab；导出功能移入设置页的「导出与备份」。
- 新增“统计”页。
- “历史”仍是周趋势 / 每日明细两块，不动。

### 统计页

统计页内部两块，使用和历史页相同的分段 tab + 左右滑动：

```text
统计
[ 分类统计 ] [ 分类管理 ]        ← 左右滑动切换

分类统计：
  周 / 月 / 年        分类设置（可选入口）
  ‹ 2026年11月 ›
  合计概览
  环形占比
  时间趋势（合计 / 单类 两版）
```

- 统计页不使用主 tabbar 的第五个位置；主 tabbar 保持 4 个。

### 设置页

  - 数据 section 的提示从“到导出页备份”改成“到设置 → 导出与备份”。

## 2. 统计页 v2

### 2.1 周期与口径

- 周从周一开始；月按自然月；年按自然年。
- 按**起床日**归属，沿用 `buildDayMetrics`；同一天多条周期相加。
- 只统计清醒分类：工作 / 日常 / 自定义 / 未分类 / 睡前时间（待分配）；补觉不计入。
- 进行中的周期按 `now` 截断。
- 当前周/月/年未结束时，与上期**相同已过天数**比较，标签写「同期」。
- 日均按“有记录的天数”算，并显示记录天数。
- 百分比用最大余数法，图例与总时间合计为 100%。

### 2.2 两版趋势

**合计版（默认）**
- 每个时间桶一根按分类堆叠的柱。
- 折线为所有清醒分类之和（等于柱顶）。
- 适合看构成和总量变化。

**单类版**
- 顶部分类选择（横向 chip，可换分类）。
- 柱子和折线只显示所选分类；纵轴按该分类的最大值重新缩放。
- 顶部显示该分类的合计、占比、日均、与上期同期变化。
- 适合看小占比分类（例如 2%）的趋势，不会在合计坐标轴下压成一条平线。
- 环形图仍显示所有分类的构成；点环形图某一段可以直接切到单类版并选中该分类。

两版共用周期、总时间列表和环形图；切换只改变趋势图。

### 2.3 数据与颜色

- 新增 `src/core/categoryStats.ts`（纯函数）：
  - 从每日 `categoryMs` 聚合周/月/年；
  - 计算上期同期、占比、两版趋势数据；
  - 处理空周期、多条周期、进行中周期、停用/未知分类。
- 颜色稳定按分类 ID：
  - 系统分类固定色：工作蓝、日常绿、未分类灰、补觉单独、睡前时间琥珀色。
  - 自定义分类按 ID 哈希到固定色相，改名/停用/排序都不变色。
- 停用分类保留历史时间，显示「已停用」；新增分类有记录后才出现。
- 未知 ID 用 `completeCategories` 补成“待确认分类”占位。

## 3. 睡前时间（待分配）

### 3.1 现在的行为（观察）

- 原生 `TimerRepository.lap()` 在封口当前段后，新开的段固定使用 `CATEGORY_UNCLASSIFIED`（`TimerRepository.java:83`）。
- 第二天开启新周期时，`applyLiveState` 会把旧周期最后一个开放段的结束时间封到新周期的 `sleepAtMs`（`src/data/store.ts:366-380`），但不会改它的分类。
- 所以“最后一次计次 → 去睡觉”的时段现在是**未分类**，这就是你看到的现象。

### 3.2 新语义

新增系统分类：

- ID：`pre-sleep`（稳定，不随改名变化）
- 默认名：`睡前时间（待分配）`
- 颜色：琥珀色，和普通分类区分
- 不能删除/停用；只能改名
- 只能作为“当前段原本就是它”的可选项；普通段不能主动选它
- 统计里正常显示；分配后时间自动转到新分类
- 统计/分类管理里可以显示一个小的“待分配”标记（按 ID 判断，不随改名消失）

### 3.3 自动打标时机

只在“开启第二天”收口旧周期时：

1. 旧周期最后一个段是**开放段**；
2. 分类仍是 `unclassified`；
3. 时长 > 0；
4. 新周期的 `sleepAtMs` 晚于该段开始。

满足时把该段分类改为 `pre-sleep`，结束时间仍封到 `sleepAtMs`；备注、来源、段 ID、时长都不改。前面更早的未分类段不动；补觉段不动；已经被你改过分类的最后一段不动。

“结束本周期”按钮**不自动打标**，避免白天误点把普通未分类段标成睡前时间。需要时可给最后一段一个手动“设为睡前时间”入口（可选）。

### 3.4 分配

- 在统计页的「睡前时间」卡片点「去分配」：
  - 列出本周期/本月的待分配段（日期、起止、时长）；
  - 点一段复用现有 `SegmentEditor`，选一个真实分类保存；
  - 保存后该段从 `pre-sleep` 移走，占比、总时间、环形图立即更新。
- 也可以走历史 → 每日明细 → 点最后一段 → 改分类；效果相同。
- 拆分段时，原分类是 `pre-sleep`，各子段可以分别分配；分配后剩余待分配时间继续保留。
- 不建议在统计页做批量自动分配；分类是语义判断，应该由你点。

### 3.5 旧数据与迁移

- **不自动改写历史**。现有已经变成未分类的最后一段，保持原样；新版本只处理未来“开启第二天”的收口。
- 可以提供一个**可选的一次性回填**：
  - 只列出“最后一个段为未分类、且结束于周期关闭时刻”的周期；
  - 先显示会改多少条、哪些日期；
  - 你确认后才写；
  - 可撤销（记下原分类）；默认不执行。
- 不做 schema 版本升级：分类目录是加法；`pre-sleep` 通过 `defaultCategories` / `completeCategories` 补进旧数据。第一次保存时 `data.json` 会多这个分类定义，不改周期/段/备注。
- 实施前仍按惯例先做只读备份；任何回填都要二次确认。

### 3.6 分类规则改动

| 位置 | 改动 |
|---|---|
| `src/core/categories.ts` | `SYSTEM_CATEGORY_IDS` 加入 `pre-sleep`；区分“固定名系统类”（未分类/补觉）和“可改名系统类”（睡前时间）；`completeCategories` 保留睡前时间的自定义名称；`parseCategories` 允许改名、拒绝停用；`changeCategories` 允许 rename、拒绝 delete/restore/up/down；`selectableCategories` 仅在原分类为 `pre-sleep` 时包含它 |
| `src/data/store.ts` | 收口旧周期时按 3.3 打标；只改开放尾段，不动历史其他段 |
| `src/components/CategoryManager.tsx` | 增加系统分类行：可改名、无删除/停用/排序按钮，说明“系统标签，仅可改名” |
| `src/pages/Stats.tsx` | 待分配卡片、分配入口、图表包含 `pre-sleep` |
| `src/data/restore.ts` | `pre-sleep` 名称冲突按普通分类处理（或明确本机优先）；不能恢复成已停用 |
| 导出 | `categorySummaryText` / JSON 自动包含；名称用当前目录 |
| 原生 | `TimerState.isCategory` 已接受 `pre-sleep`；不需要新增原生常量；打标在 JS 收口时写入并落盘 |

### 3.7 测试

- 开启第二天：旧周期开放尾段未分类 → `pre-sleep`，时长/备注/ID 不变。
- 尾段已分类 / 是补觉 / 时长 0 → 不变。
- 旧周期已手动结束、没有开放段 → 不自动打标。
- 前面的未分类段不被误标。
- `pre-sleep` 可改名，刷新/重开后名称保留；不可删除/停用；普通段不能选它；原段可以改成真实分类。
- 统计包含 `pre-sleep`；分配后原分类减少、目标分类增加，总量不变。
- 旧备份没有 `pre-sleep` 时自动补；带改名的备份恢复后名称正确。
- 回填工具的预览数量、确认、撤销。

## 4. 分段与计次手感

### 4.1 现在的问题（观察）

- 拆分要打开编辑器 → 选“按日期和时刻/按经过时长” → 输入 → 添加分界 → 预览 → 再确认；表单感重，时间点不直观。
- 合并要在编辑器里选方向、选分类、再确认；没有“把两段合起来”的空间感。
- 计次按钮能用，但按下去只有状态变化，缺少触感/声音/短暂反馈。
- 这些都是交互层问题，不改数据模型。

### 4.2 拆分：上下拨刻度

预览：`docs/previews/segment-tools-preview.html`（点时间段 → 拆分）。

- 整块垂直刻度，中间固定一条切分线；上下滑动刻度选择切分点。
- 1 分钟一格；5 分钟中等刻度；15 分钟长刻度 + `+15m/30m/45m` 标记。
- 顶部大字显示切分时刻；下面显示“前 1h00 / 后 1h00”。
- 首尾显示原段起止；不能滑出原段。
- 滑到 5 分钟格有轻触感/短音；15 分钟格强一点；拖动结束吸附到分钟。
- `−1 分 / +1 分` 用于精调；保留“精确输入”作为无障碍/备选。
- 切分后直接显示两段预览和分类 chip；默认继承原分类；点 chip 改分类；备注默认沿用。
- 保存按钮“拆成 2 段”，直接原子提交；出错保留修改可重试。
- 多刀：在任一段上再进入拆分即可继续切；不需要一次表单里加多个日期。
- 跨午夜：刻度上显示日期变化；保持现有的绝对时间校验。
- 进行中的段：尾段仍开放，刻度终点为“现在”。

### 4.3 合并：滑动确认

- 从时间段编辑器点“合并”，或在时间轴上点两段之间的分界。
- 显示相邻两段卡片、合计时长、合并后备注（去重）；分类 chip 选结果分类。
- 一条“向右滑动合并”的轨道；拖到 86% 以上松手才合并，减少误触。
- 达到阈值时强触感 + 音效；合并完成再给一次 success 触感。
- 保留“直接合并”按钮给键盘/无障碍/不喜欢滑动的人。
- 只在真正连续的相邻段出现；有暂停空档不显示合并。

### 4.4 计次

- 保留现有“计次后打开备注/分类”的主流程（避免改变数据录入习惯），但让按钮本身更有反馈：
  - 按下缩放 + 轻震；
  - 成功时短促“嗒”声 + 一圈扩散动画；
  - 状态条显示“已计次 14:32 · 可补备注”。
- 可选“快速计次”模式（设置里开关）：点一下只计次并弹 3 秒提示，不自动打开编辑器；长按才打开备注。默认先不做，等你在真机上试过手感再定。

### 4.5 声音与触感

**触感**
- 使用官方 `@capacitor/haptics`（Capacitor 8 对应版本，参考 <https://github.com/ionic-team/capacitor-docs/blob/main/versioned_docs/version-v8/apis/haptics.md>），Android 加 `VIBRATE` 权限。
- 刻度每 5 分钟 `selectionChanged()` 轻触；15 分钟/阈值/保存用 `impact(Light/Medium)`；合并成功用 `notification(Success)`。
- 节流：两次触感至少间隔 ~45–60ms，避免滚动时连续震。
- 没有触感硬件时调用会静默失败，不影响功能。

**声音**
- 首选 **Web Audio 合成**：短三角波/噪声 click，代码 <1KB，无版权、无网络、无额外资源；预览里已经用这种方式。
- 若你觉得合成声太“电子”，可换成公共素材；候选（需逐个确认具体文件许可证）：
  - Freesound “Synthesized UI Sounds: Clicks, Hovers and Pop-ups” by Qvantor（CC0，含 picker wheel tick/thock 类声音）：<https://freesound.org/people/Qvantor/packs/46659/>
  - Pixabay “Minimal UI pack – pops clicks ticks”（Pixabay 许可，需按站点条款）：<https://pixabay.com/ja/sound-effects/映画と特殊効果-minimal-ui-pack-pops-clicks-ticks-27052/>
  - Creazilla 的 CC0 “Click Tick” / “Minimal UI Pack”（来源标注 Freesound）：<https://dev.creazilla.com/media/audio/15467850/click-tick>
  - SFXMint 的 CC0 UI tick 集合（需确认单文件条款）：<https://sfxmint.com/sounds/ui-hover>
- 如果采用外部素材：只选一个短 tick，转 OGG，记录来源/许可证到 `docs/outcomes/`，不把未确认许可的文件打进 APK。
- 设置页加「触感与音效」：触感开关、音效开关（默认触感开、音效开；可随时静音）；分段刻度页也有一个快捷静音按钮。
- 静音/省电模式下不强行播放；声音失败不阻塞操作。

### 4.6 实现与风险

- 组件：抽出 `SplitWheel`、`MergeSlide`，替换 `SegmentSplitter` 的输入区；保留原数据层 `splitSegments` / `mergeAdjacentSegments` 校验。
- 刻度实现：1 分钟一行，CSS scroll-snap + 中心读数；段长超过 ~12 小时时限流/窗口化，避免一次渲染上千行。
- 触感/声音属于渐进增强：没有插件、没有音频权限、桌面浏览器时自动降级。
- 真机需要重点试：滚动惯性、吸附、震动节奏、WebView 音频、合并滑动误触。
- 不改变拆分/合并的原子提交逻辑，失败不写半截。

## 5. 实施顺序

建议分两步，降低一次改太多带来的风险：

**v0.7.0：统计页 + 睡前时间**
1. 主导航/统计页/导出迁移/分类管理迁移。
2. `pre-sleep` 系统分类、收口打标、分类规则、设置恢复兼容。
3. 统计两版趋势、环形图、总时间、待分配卡片。
4. 单测 + 构建 + 浏览器 375/360；备份后同签名装机，读回数据。

**v0.7.1：分段手感**
1. `SplitWheel` / `MergeSlide` / 计次反馈。
2. `@capacitor/haptics` + Web Audio + 设置开关。
3. 真机调手感；保留旧输入作为无障碍 fallback。

如果你希望一次发 v0.7.0，也可以合并，但开发和真机调试时间会更长；建议先上统计和睡前时间，再单独调手感。

## 6. 需要你确认

1. **自动打标时机**：只在“开启第二天”收口时打标；手动“结束本周期”不自动打标。可以吗？
2. **旧记录**：不做自动回填；需要的话提供一个带预览和确认的一次性回填工具。你要不要？
3. **分配入口**：统计页待分配卡片直接打开段编辑器（推荐），还是只给一个跳转每日明细的链接？

5. **声音**：先用 Web Audio 合成，还是直接找 CC0 素材打包？我建议先合成，真机觉得不够再换。
6. **发布节奏**：v0.7.0 统计/睡前 + v0.7.1 分段手感，还是合成一个版本？

## 8. 观察 / 推断 / 建议的边界

- 观察：`lap` 新开段是未分类、收口时封到 `sleepAtMs`、`summarizeCycle` 会把非补觉分类计入 `categoryMs`。
- 推断：把“最后一次计次到睡觉”的开放尾段标成 `pre-sleep`，不会影响其他段；这是基于现有收口逻辑的判断，实施时用单测验证。
- 建议：统计与睡前时间先做，分段手感单独做；触感和声音都做开关，不把体验强加给静音场景。
