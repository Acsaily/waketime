## 交付的功能（对应本轮三个问题 + 两个新功能）

- 起床后到首段之间的漏记不再丢失：原生新周期首段从 `wakeAtMs` 开始；旧记录会插入独立的「起床后未记录（补齐）」段，**不挪用原首段备注/类别**。JS 与原生采用同一规则，防止 live 刷新把修复抹掉。
- 手滑双击计次产生的相邻连续段可手动合并：只允许相邻且精确连续的两段（不跨暂停空档），合并后类别由用户显式选择，两段不同备注换行保留、完全相同的只保留一次；第二段为进行中时合并后仍进行中。原生与数据层同一套边界校验。
- 补觉：实时「开始补觉 / 结束补觉」按钮，也可事后把已完成段标为补觉。总睡眠 = 主睡眠 + 补觉；实际清醒排除补觉；参考截止固定为 `主睡眠入睡 + 24h`，不因补觉顺延。补觉中不能计次，通知动作变为「结束补觉」，秒表显示暂停但参考剩余按真实时钟继续。
- 工作 / 日常分类：计次后编辑刚结束段的备注与分类；旧记录默认「未分类」，不根据备注猜测。历史与当日都显示 工作 / 日常 / 未分类 / 总睡眠 汇总，并同步到 TXT / JSON / PDF 导出与趋势（趋势睡眠时长改为含补觉的总睡眠）。
- 界面可读性：趋势图柱顶文字与入睡/起床标签分开成行不再裁切重叠；设置说明不再显示 Markdown 星号；target 36 边到边下状态栏改为浅色图标适配深色底。

## 数据安全

- `category` 为可选字段，旧备份向后兼容；沿用 schema 1，避免旧备份被误判损坏。
- 读取时自愈去重、负时长段丢弃、起床空档补齐，均在写入前校验；空记录是合法新用户状态。
- 恢复候选从最近 5 份改回**最近 20 份**（与文档一致）；备份仍保留 20 份。单个坏候选不阻断其余恢复路径；主文件读不出来时不再被当作“新用户”静默覆盖。
- 编辑/合并/补觉操作先 `getState` 同步通知栏最新段，再串行写入；失败不吞错误，不留半次变更。关闭周期先快照结束态再清原生，不丢最后一段。
