# 自定义分类与手动补分段：更新方案（待用户确认）

日期：2026-11-06。性质：代码与文档核对后的建议，不是已采纳决定，也不是已实现功能。

## 预期产出与完成标准

建议作为 v0.5.0 同一轮更新：允许管理清醒类别，允许把漏计次形成的大段拆成连续小段；今日、历史、统计、导出和备份恢复使用同一套类别与分段结果。旧记录、原备注和原时间范围不得因升级而丢失，当前计时不得被事后编辑打断。

本轮仅提交方案文档；不修改功能代码、不连接或改动手机数据、不构建、不提交或推送。

## 判断与观察到的事实

- **CONTINUE + REUSE**：沿用 v0.4.0 的段编辑器、相邻段合并、JS 历史编辑与原生活动周期编辑分流、串行保存与恢复机制。
- 权威状态是 `docs/project/STATUS.md`：v0.4.0 已装机冒烟，部分交互仍待用户真机试用；INDEX、README 的部分说明尚未同步。
- `src/native/contracts.ts`、`src/core/segments.ts` 与 Java `TimerState` 将类别写死为 `work/daily/sleep/unclassified`。
- `src/data/store.ts` 的校验会拒绝其他类别，JS 清洗和原生序列化也会把未知类别转成未分类。只增加界面按钮不足以实现自定义类别。
- 汇总当前固定为工作/日常/未分类；今日、历史、导出预览、TXT/PDF/JSON 都需要一起适配。
- 活动周期以原生为准，回到前台时会整份镜像；分段不能只改 JS，否则可能被下一次同步覆盖。
- 原生段除墙上时间外还有单调钟锚点；拆分进行中段需要保留有效计时锚点。
- 当前设置恢复入口只提取 cycles，即使全量备份含 settings 也不恢复；新功能必须补上标签目录的恢复，不能照搬这个入口。
- 已有合并只能处理相邻且精确连续的段，不能跨暂停空档；补分段应复用同样的连续性原则。
- 本轮未运行单测或构建；STATUS 里的既有通过数是历史证据，不代表本轮重新验证。

## 建议一：自定义分类（界面可以称为“分类标签”）

### 交互

设置页增加“分类管理”：新增、改名、上移/下移、删除；已删除但仍被历史引用的类别可在“已停用”中恢复。

- 初始保留工作、日常。二者和新增类别一样可改名、停用，不强制用户继续使用。
- 每段仍只选一个类别，备注继续自由填写；不在本次变成多标签，避免同一时长重复汇总。
- 未分类是系统兜底，不允许删除；补觉是影响睡眠计算的系统状态，不作为普通自定义类别删除或改语义。
- 常用备注与类别分开管理；不根据文字自动判断类别。
- 名称去首尾空白、禁止空名和重复名；长度建议 1–12 个字，正式实施时按统一字符规则校验。系统名称保留，避免新建“补觉”却被当作清醒时间。
- 段编辑、计次后的编辑、合并、补分段均使用同一份类别目录。

### 改名与删除的历史规则

- 段引用稳定 ID，不拿名称作为主键；改名后历史和导出统一显示新名称，时长、备注不变。改名界面提示会同步历史显示。
- 删除没有引用的类别：确认后可以真正移除。
- 删除已有记录引用的类别：界面明确提示“从新记录选项中移除，历史仍保留”，内部停用，保留 ID 和名称；不偷偷把旧段改成未分类，不删除旧段。
- 已停用类别仍参与历史与汇总；编辑原有记录时可保留原类别，但不能给其他记录新选这个停用类别。
- 本版不做批量迁移历史类别，以免误操作扩大影响。

### 统计

工作/日常固定字段改为按类别 ID 聚合。默认按管理顺序展示，零时长自定义项可收起；历史引用的停用项有时长时照常显示。

清醒类别合计 + 未分类 = 实际清醒。延续现有口径：暂停空档归未分类，补觉不计入清醒。若保留旧 JSON 的 workMs/dailyMs 兼容字段，它们仅表示原 work/daily ID 的汇总，不能取代新动态汇总。

## 建议二：手动“补分段”

### 推荐操作流程

时间轴点某段 → 编辑器中的“拆分这一段” → 添加一个或多个分界点 → 给每个子段分别选类别、改备注 → 预览 → 一次确认保存。

例：原段 09:00–12:00，漏记了中间的吃饭和工作切换：

```text
09:00–10:20  工作  写方案
10:20–10:50  日常  吃饭
10:50–12:00  学习  看资料
合计仍为 3 小时
```

- 首先输入“几点几分”，跨午夜必须明确标注日期/次日，不只显示相同的时钟数字。
- 提供“从段开始经过多久”的辅助输入；每次修改都转换成同一个分界时间点，不维护两套相互独立的时间数据。
- 一次可增加多个分界点并删除草稿分界点，不必反复拆两段、保存、重新打开。
- 原备注在编辑页展示，默认每个子段预填原备注并提示这是复制，用户可分别修改；不自动猜哪句话属于哪段。
- 默认继承原类别，可逐段调整；确认前显示每段起止、时长、类别、备注及合计。
- 取消不改任何记录；无有效分界点时不允许保存。

### 时间约束

- 分界点必须严格位于原段内部，按升序排列、不能重复，不得产生零或负时长段。
- 子段首尾精确相接，保留原段最外侧起止时间；内部使用毫秒，不因界面只显示分钟就截断原始秒数。
- 不允许跨越暂停空档、另一段、另一周期，也不改睡眠录入的主睡眠边界。
- 拆分本身只改变边界，不改变总覆盖时长。调整清醒类别只改变分项；用户把已完成子段改成补觉时，睡眠/实际清醒按现有规则重算，参考截止不顺延。
- 拆后按时间重排 seq；保留一段原 ID，其余生成新 ID，并记录拆分来源以便追踪。不要把现有 source 的 app/notification 语义改成另一种来源枚举。
- 页面、通知栏称“记录段数/已完成段数”，拆分后按实际段数更新，避免被理解为真实点击次数；本次不另建点击次数统计。

### 今日与历史

- 已完成的今日段与历史段都可拆分，包括已完成补觉段。
- 进行中的清醒段也支持补分段：只在已发生的时间内加分界点，最后一段继续计时，不需要先点计次或结束计时。
- 开放尾段仍为清醒类别，不能借拆分绕过“开始/结束补觉”去切换实时状态；已结束的前部子段可以补记为补觉。
- 正在补觉的开放段先结束补觉后再拆，维持当前实时补觉状态保护规则。
- 编辑期间原生计时继续；预览尾段标“进行中”，保存时尾段延续到实际当前时刻，不把打开编辑器的时间当作结束时间。
- 保存携带周期 ID、目标段 ID 与预期版本/边界；原生同步校验。若通知栏计次、合并、周期切换等导致目标变更，拒绝旧草稿提交并提示重新打开，不覆盖新记录。
- 新增原生原子拆分操作，校验后一次持久化；原生重新处理单调钟锚点，不能直接拷贝一份陈旧 JS 段列表覆盖原生状态。

### 纠错

保留现有相邻合并作为拆错后的修正入口；合并需明确选结果类别，备注按现有去重换行规则保留。它是修正工具，不声称能精确撤销已编辑过的备注；本版不承诺完整操作历史或多级撤销。

## 数据与兼容建议

- 类别目录放进持久化设置，条目至少有稳定 id、名称、顺序、停用状态；继续保留 work/daily/unclassified/sleep 的既有 ID，新增类别使用唯一 ID。
- JS 类型、归一化/校验、原生读写与插件接口统一支持自定义 ID；原生计时逻辑仅对保留的 sleep ID 作睡眠特殊处理。未知引用不得静默丢弃或重分类，导入时补齐为显式的待确认/停用目录项。
- 建议新数据采用 schema 2，明确支持 schema 1 导入与迁移。不能直接把当前 SCHEMA_VERSION 改成 2 而不修改读取/恢复路径；未来未知 schema 仍拒绝并保护原文件。
- 改动数据层前先取得并校验当前真机全量备份、活动原生状态和源码快照。旧的 2026-10-29 备份不能替代本次升级前备份；不以清空或替换用户 data.json 作为迁移/测试手段。
- 新备份包含类别目录、周期数据、必要的分段元信息和动态汇总；单日 JSON 也携带足以解释类别的目录项。
- 恢复时校验并预览类别和记录。覆盖恢复保留本机无关设置；合并恢复保留本机目录并引入备份引用的类别，ID 冲突且定义不一致时显示冲突供确认，不按同名自动合并或静默改写历史。
- 迁移、损坏恢复和导入在隔离副本验证；保留原备份可回退，不声称旧 APK 能读取 schema 2，也不建议直接降级 APK 验证。

## 实施范围与建议顺序

1. 先做最新备份和基线验证，再完成类别目录、兼容迁移、校验与原生保存。
2. 接入分类管理、今日/历史/段编辑/合并的动态类别和统计。
3. 实现 JS 历史拆分与原生活动段拆分，接入预览和冲突保护。
4. 同步 TXT/PDF/JSON、全量备份与恢复入口。
5. 跑单测、前端构建、原生单测、安卓构建，再同签名覆盖安装真机验证；交付是否命名 v0.5.0 以用户确认和实际完成为准。

不纳入本轮：多标签、分类层级、自动猜类别、提醒/自动化、任意拖拽修改时间范围、跨段重排、OCR、日历补录和复杂撤销系统。

## 验收标准（实施后逐项取证）

- 新建“学习”可在今日、历史、合并、拆分中使用；重启/切后台/通知栏计次后不变成未分类。
- 工作/日常可改名或停用；已引用类别删除后历史名称、备注和时长仍在，新记录不再提供该类别。
- 拆分 3 小时为多个清醒子段后精确合计仍是 3 小时；已完成段起止不变、无重叠空隙，纯拆分不改变睡眠/清醒总量。
- 覆盖今日、历史、跨午夜、原始带秒的时间、重复/越界分界点、短段、多分界点和补觉分类的测试。
- 进行中段拆分后唯一开放尾段继续计时；通知栏计次并发、系统时间异常、重启和写盘失败不产生半次拆分或覆盖新数据。
- 页面与 TXT/PDF/JSON 的动态分类、停用项和补觉汇总一致。
- schema 1 旧备份迁移成功；新备份在隔离数据中恢复后类别定义、记录、备注和拆分边界一致；损坏或不兼容数据拒绝且原数据保留。
- 真机截图与导出读回文件作为交互证据，构建成功不能替代真机验证。

## 待用户确认

建议整体采用：单类别模型；有引用的删除按停用处理；改名同步历史显示；未分类/补觉保留系统语义；支持多分界点和进行中清醒段的补分段；不做任意修改外侧起止时间。
